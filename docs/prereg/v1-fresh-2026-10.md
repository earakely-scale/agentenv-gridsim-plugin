# GridSimEnv v1, fresh days 2026-10-18 to 2026-10-27: live foresight evaluation (pre-registration)

Committed and pushed before any model generation on any task below, including the pipeline check. There is no
training in this lane. This is the **first entry of a running scoreboard** (FD-4420), not a registered claim: 10 days is
a small sample, and every gap below is reported with that caveat.

## Why
Every model in this repo was trained on 2014–2024 days, and the newest eval pack, rtcb, ends 2026-10-17. The ten days
after it cannot be in any model's training data. The last of them, **2026-10-27, had not happened yet** when this was
written: ERCOT posts the day-ahead prices for D+1 at about 13:30 CPT on day D, and the foresight tier needs only those
prices. All ten days fall after RTC+B (2025-12-05), the market design where the trained 4B is weakest.

## Tasks: `ercot-dam-v1-fresh-2026-10` (commit 252327b)

    same. The reason is sample size: one draw leaves 98 tasks, about 10 a day;
  - **dropped:** rtcb's stratified subsample to a target size. Every surviving task is kept;
  - **no day-level filter fires:** every day keeps 15–53 tasks, and 2026-10-27 keeps 35.
- Each task carries its DP optimum, idle, greedy, threshold, clock and random references. Re-running

## Statistics
- **Mean R per model**, with a 95% CI from a **block bootstrap over days**: resample the 10 days with replacement
  (10,000 resamples, seed 0), keep every task of each drawn day, take the task-weighted mean. Tasks within a day share
  its price shape, so this is the honest CI. The **naive task-level bootstrap** (362 tasks, 10,000 resamples) is also
  given, labelled as such; it is too narrow.
- **Paired differences**, same tasks, the same day-block resampling applied to the per-task difference:
  - run 3 − greedy rule;
  - run 3 − SFT-10k;
  - run 3 − Sol;
  - SFT-10k − greedy rule.
  Each is computed for the sampled (primary) and greedy decodings, with the naive task-level CI alongside. A gap is
  **shown** when its day-block CI lies wholly on one side of 0, and **not shown** otherwise. There is no multiplicity
  correction and no pass/fail bar: this is a scoreboard entry.
- **2026-10-27 on its own (descriptive):** each model's mean R on its 35 tasks and the same four gaps, with a task-level
  CI labelled within-day. One day carries no claim.
- **Error mix per model:** valid, feasible, overfill, sell-before-charge, end-short, cycle cap, rate, all-idle, and
  invalid (malformed or truncated).
- **Also reported:** per-day means (a chart), R by start state, the draw-1 subset (98 tasks, exactly rtcb's archetype
  rule), the clock rule, and Sol's tokens and spend.

## Rules
- One pass per (model, decoding). Nothing is rerun to improve a score; no checkpoint picking, no prompt change.
- A crash from an infrastructure fault is rerun with the same command and logged; only a completed pass is scored.
- **Order:** pipeline check, then the 4B fresh passes (GPUs 0–1), Sol (from a laptop) in parallel.
